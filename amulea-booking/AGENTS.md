# Amulea 予約アプリ — 作業引き継ぎ

プライベートリラクゼーションサロン **Amulea** の予約システムです。
お客様は公式LINEのリッチメニュー「予約」から開きます。

このファイルは、作業を引き継ぐ担当者（人・AI問わず）向けの説明書です。

> **ホームページとは別のアプリです。**
> リポジトリ直下の `package.json` がホームページ、
> このフォルダの `package.json` が予約アプリです。混同しないでください。
> ホームページ側の説明は、リポジトリ直下の `AGENTS.md` にあります。

---

## 1. いちばん大事な原則

### 1-1. メニューと料金をコードに書かない

メニュー・料金・営業時間・休業日は、**管理画面から編集できる**必要があります。
`lib/domain/defaults.ts` にあるのは「まだ一度も設定されていないときの初期値」だけです。
画面のコードに金額や時間を直接書かないでください。

### 1-2. 空き時間の判定は必ずサーバー側で行う

画面は `/api/availability` の結果を表示するだけです。**画面側で判定しないでください。**
二重予約が成立すると、お客様を同じ時間に2人お迎えすることになります。

### 1-3. 秘密情報はコードに書かない

APIキー・秘密鍵は `.env.local`（Git管理外）と Vercel の環境変数だけに置きます。
`lib/config/env.ts` が唯一の入口です。他の場所で `process.env` を読まないでください。

## 2. 技術構成

| | バージョン |
| --- | --- |
| Next.js（App Router） | 16.3.2 |
| React | 19.1.1 |
| TypeScript | 5.9.3 |
| Tailwind CSS | 4.3.3 |
| Node.js | 22 系 |

**追加ライブラリはありません。** Google認証（RS256のJWT）、セッションの署名（HMAC-SHA256）、
管理者パスワード（scrypt）、予約ID（UUID）はすべて `node:crypto`、
外部通信はすべて標準の `fetch` です。

公式SDKを入れていないのは、ライブラリの更新で動かなくなる事故を避けるためと、
他人のコードが混ざる経路を作らないためです。**新しいライブラリを足す前に、
本当に必要か検討してください。**

```bash
npm ci            # 初回のみ
npm run dev       # 開発サーバー http://localhost:3000
npm run build     # 本番ビルド（SESSION_SECRET が必要）
npm run typecheck # 型チェック
npm run e2e       # 統合テスト（65項目）← 変更後は必ず実行
```

## 7. 踏んだ落とし穴（再発防止）

**同じ失敗を繰り返さないよう、必ず目を通してください。**

### 7-1. LIFFの認証は「トップページ」にしか戻ってこない

LINEは認証が終わると、**LIFFに登録されたエンドポイントURL（＝トップページ）へ必ず戻します。**
`/booking` から認証へ送っても、戻り先はトップページです。

以前、トップページが何もしていなかったため、お客様は
「予約ボタンを押す → ホームに戻される」という状態になりました。

現在はトップページを `SessionGate` で包み、**ログインを先に済ませる**設計です。
サブページから認証が必要になった場合は、行き先を `?next=` に載せてトップへ送り、
ログイン成立後にそこへ移動します。

- `?next=` は「/」で始まり「//」で始まらない値だけ許可（外部サイトへの誘導を防ぐため）
- 認証から戻っても未ログインなら、**往復を繰り返さず**案内を出して止める

**トップページから `SessionGate` を外さないでください。**

### 7-2. LINEアプリ内ブラウザでは、画面の差し替えが失敗することがある

App Router の「JavaScriptで画面だけ差し替える」方式は、リンク本来の動作を
JavaScript側で打ち消したうえで差し替えます。これが失敗すると
**押しても何も起きず、エラーも出ません。**

お客様側の画面は、素の `<a>` とページ全体の読み込みを使っています
（`components/ui/Button.tsx` の `ButtonLink`、`lib/client/navigate.ts`）。
全ページがログイン確認から始まるため、差し替えによる速度の利点はありません。

**`next/link` や `useRouter` をお客様側の画面に戻さないでください。** 管理画面は通常のブラウザで使うため対象外です。

### 7-3. ルートの `tsconfig.json` がこのフォルダを巻き込む

リポジトリ直下の `tsconfig.json` の `include` がこのフォルダを拾うと、
**ホームページのビルドが壊れます**（`Cannot find module '@/...'` が大量に出ます）。
`exclude` に `amulea-booking` が入っていることを確認してください。

### 7-4. Vercel の Framework Preset

`Other` のままだと `No Output Directory named "public" found` でビルドが失敗します。
`vercel.json` に `{"framework": "nextjs"}` を置いて解決済みです。

### 7-5. ルートレイアウトの `force-dynamic`

`app/layout.tsx` の `export const dynamic = "force-dynamic"` は外さないでください。
ビルド時の先読みでデプロイが失敗するうえ、個人情報を含む画面をキャッシュさせないためにも必要です。

### 7-6. Googleの秘密鍵は `private_key_id` と取り違えやすい

JSONをメモ帳で開いて `private_key` を検索すると、**1つ手前にある `private_key_id` が先に見つかります。**
実際にこの事故が起きました。

対策として `GOOGLE_SERVICE_ACCOUNT_JSON` に**JSONを丸ごと貼る方式**を用意し、
診断ページが形から取り違えを検出して名指しします（`app/api/admin/diagnostics/route.ts`）。

### 7-7. LINEログインチャネルは「公開」に切り替える

「開発中」のままだと、開発者本人以外は
`400 Bad Request / This channel is now developing status` になります。

### 7-8. スプレッドシートの読み取り失敗は、設定と予約で扱いを変える

- **設定**の読み取り失敗 → 初期値で継続してよい（画面が真っ白になるのを防ぐ）
- **予約**の読み取り失敗 → **握りつぶさない**。空き枠に見えて二重予約になります

`lib/store/sheets.ts` の `readSetting` にこの使い分けがあります。

### 7-9. 診断ページは「壊れているとき」に到達できる場所に置く

設定の読み込み失敗で早期 return すると、肝心の診断が表示されません。
`/admin/settings` は設定が読めないときでも診断を表示します。

### 7-10. 管理画面の初期パスワード

`ADMIN_PASSWORD_HASH` が未設定だと、開発用の既定パスワードのまま動きます。
管理画面に入られると**全お客様の氏名と電話番号が見えます。**
ハッシュは `npm run hash-password "パスワード"` で作れます。

## 8. 作業の進め方

変更したら、**必ず `npm run e2e` を実行してから** push してください。

```bash
npm run typecheck
npm run build
npm run e2e        # 65項目
```

テストは本番と同じビルドを起動し、HTTP越しに次を確認します。

公開API／セキュリティヘッダー／ログイン／管理APIの保護／営業時間と祝日の判定／
**二重予約の防止**／**他人の予約に触れられないこと**／CSRF／入力検証／
変更・キャンセルで枠が戻ること／管理画面／**ログに個人情報が残らないこと**

> テスト用サーバーは必ず `MOCK_MODE=true` で起動します。
> Google・LINE へ一切接続しないため、手元に本物の `.env.local` があっても
> **本番のカレンダーにテスト予約が入る事故は起きません。**

LINEアプリ内の挙動は、ヘッドレスブラウザで `window.liff` を
`isLoggedIn` / `getIDToken` だけ持つ偽物に差し替えて検証できます。

### オーナーへの説明について

このシステムのオーナーは、パソコンの操作に慣れていません。
Google Cloud・LINE Developers・Vercel の操作をお願いするときは、
**ファイル名を指すだけでなく、手順をその場に、クリック単位で書いてください。**

不具合の原因が分からないときは、推測を重ねるのではなく、
**原因を切り分けられる診断手段を先に作ってください**（`/check` はそうして生まれました）。

## 10. 経緯（なぜこうなっているか）

- もともと旧公式LINEがありましたが、**2026年8月に管理者によって削除**されました。
  削除された公式アカウントは復活できず、IDもQRも再利用できません。
  現在のLINEチャネルは作り直した2代目です。
- 保存先は当初からスプレッドシートですが、`DataStore` という共通の窓口を挟んであります。
  将来データベースへ移すときは、この窓口の中身だけ差し替えれば、
  予約画面や通知のコードを触らずに済みます。
